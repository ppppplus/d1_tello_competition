# 入楼流程验收（2026-10-21）

本次使用 ROS 2 Humble / Gazebo Fortress 6.16；原 D1 步态权重与动力学保留。

- 默认 2 号着火窗：完整比赛 **3/3 通过**，用时 322.141 秒仿真时间；完成平地、转向、8 级楼梯、打靶、两次投放、集合与楼外降落。
- 实测无人机在 `(7, 1.5, 1.8)` 附近穿入、从同一窗户飞出；D1 在 `(1, 1.5)` 附近走入独立地面门。
- 1/3 号着火窗：分别通过穿窗、首报、机器狗进门检查；这两项仅验收入楼段，不作为全程比赛验收。
- 刻意从非着火窗穿入：在首次目标报告前判为 `uav_invalid_window_entry`，没有计入任务成绩。
- 学生模式的 `student_enter.py`：等待首报、转向、穿门并停稳通过；继续运行至 140 秒，巡查结束后无人机保持楼内悬停，没有自行穿墙返回楼外。
- 新增入口观察相机与无人机前视相机均收到 ROS 2 RGB 图像；姿态控制改为世界坐标四元数误差后，全程无人机最大倾斜 9.75°。
- 实体门窗开口、连续位姿穿越与机体完全入楼状态同时核对；没有通过瞬移机器人实现进楼。

复现默认全程：

```bash
ros2 launch d1_tello_competition competition.launch.py gui:=false rate:=0 exit_on_finish:=true fire_window:=2
```

结果目录的 `result.json` 应包含 `strict_pass: true`、`completed_count: 3` 及 `entry_validation.passed: true`。
着火窗仍由配置选择，演示使用已知航点；前视相机是学生实现视觉识别的接口，不代表已实现自动识别。
