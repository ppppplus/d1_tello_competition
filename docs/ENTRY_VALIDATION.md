# 六扇小窗与入楼流程验收（2026-10-21，v1.2.0）

这是 v1.2.0 的历史记录；当前地图与二楼集合规则见 [v1.3 地图调整验收](MAP_VALIDATION.md)。

本次使用 ROS 2 Humble / Gazebo Fortress 6.16；D1、Tello 的模型尺寸、D1 步态权重与动力学保持原样。

- 外立面改为上下两排、每排三扇窗，净开口均为 **0.6 × 0.6 m**。下排 1–3 号窗中心高 1.3 m，上排 4–6 号窗中心高 2.5 m；每排中心横坐标为 4、7、10 m。绿色独立地面门保持宽 1.4 m、高 1.05 m。
- 六个窗位分别通过实际物理仿真的穿窗、楼内首报、机器狗进门检查。1/3/4/5/6 号窗各运行 75 秒，仅验收入楼段；不作为这五个窗位的全程比赛验收。
- 默认下排 2 号着火窗：完整比赛 **3/3 通过**，用时 **322.141 秒仿真时间**；完成平地、转向、8 级楼梯、打靶、两次投放、集合与楼外降落。
- 独立读取连续位姿并插值检查：无人机于 19.612 秒在 `(7, 1.5, 1.300)` 附近穿入，于 307.360 秒从同一窗飞出；D1 于 45.229 秒在 `(1, 1.5)` 附近走入地面门。首次目标报告为 37.655 秒，D1 完全入楼为 48.159 秒，顺序符合规则。
- 两次投放落点误差分别为 0.1508 m、0.1488 m；红靶记录到弹体与靶板的实体接触。
- 上下排反例：着火窗选下排 2 号，故意从同横坐标的上排 5 号窗穿入，在 22.401 秒被判为 `uav_invalid_window_entry`；此前没有首次目标报告，任务完成数为 0。窗位判定包含高度。
- 核对实体门窗开口、连续位姿穿越与机体完全入楼状态；没有通过瞬移实现进楼。入口视频为实际 Gazebo 相机采集，约 30.3 帧/秒。

复现默认全程：

```bash
ros2 launch d1_tello_competition competition.launch.py gui:=false rate:=0 exit_on_finish:=true fire_window:=2
```

`fire_window:=1` 至 `fire_window:=6` 可切换着火窗，红圆标记、入楼航点、出楼航点与通行判定同步变化。
结果目录的 `result.json` 应包含 `strict_pass: true`、`completed_count: 3` 及 `entry_validation.passed: true`。

着火窗由配置选择，教师演示使用已知航点；前视相机是学生实现视觉识别的接口，不代表已实现自动识别。
